# بازسازی محلی پنل مدیریت میزکار

این پروژه یک بازسازی مستقل و راست‌چین از پنل مرجع Mupra است که برای تحلیل محصول، استخراج جزئیات فرم‌ها و طراحی نسخه‌ی نوین آماده شده است. داده‌های اولیه عمداً خالی‌اند؛ سناریوی کافه‌رستوران فقط از طریق فرم‌های واقعی خود برنامه وارد می‌شود و هیچ داده‌ای از حساب واقعی سایت مرجع در آن ذخیره نشده است.

## محتویات

- داشبورد مدیریتی با کارت‌های شاخص، نمودار فروش/هزینه و کانال‌های فروش
- پوشش ۷۵ مقصد استخراج‌شده از نسخه‌ی زنده به‌همراه صفحه‌ی اختصاصی رسپی؛ در مجموع ۷۶ نمای قابل پیمایش
- منوها و زیرمنوهای محصولات، صورت‌حساب، باشگاه مشتریان، کمپین، نظرسنجی، انبار، رزرو، KDS، مالی و تنظیمات
- جدول‌های راست‌چین با جست‌وجو، مرتب‌سازی، فیلتر، جمع‌بندی، انتخاب ستون، صفحه‌بندی و خروجی سازگار با Excel
- عملیات ردیف متناسب با هر صفحه: ویرایش/حذف، مشاهده، تأیید، عملیات شش‌گانه‌ی صورت‌حساب و عملیات گروهی اختصاصی محصولات
- فرم‌های جزئی برای دسته‌بندی، محصول، افزودنی، رسپی، انبار، مشتری، تراکنش مالی، هزینه، تنظیمات و سایر گردش‌کارها
- زنجیره‌ی متصل محصول و رسپی با ساخت خودکار رسپی، مقدار مصرف، پرت، انبار مصرفی، کنترل کسری، بهای تمام‌شده و سود ناخالص
- فاکتور ورود انبار، خروج/انتقال چندقلمی، برنامه‌ی تولید دومرحله‌ای، انبارگردانی، ضایعات و گزارش بهای تمام‌شده
- اتصال فروش به لیست صورت‌حساب، KDS، دریافت مالی و خروج مواد رسپی از انبار؛ جلوگیری از فروش در صورت کسری ماده
- اتصال خرید انبار به گردش موجودی، هزینه‌ی مواد اولیه و پرداخت مالی؛ اتصال هزینه‌ی پرداخت‌شده به دفتر مالی
- فرم‌های چندردیفی برای مواد هر انبار، شرط‌های کمپین و آدرس‌های متعدد مشتری/شخص
- نگهداری داده‌های عملیاتی و تنظیمات جدول در مرورگر محلی پس از تازه‌سازی صفحه
- ذخیره‌ی فرم‌ها در D1 محلی از مسیر API
- اسکیمای رابطه‌ای SQLite/Drizzle شامل ۱۴ جدول اصلی
- فونت‌های محلی YekanBakhFaNum و طراحی واکنش‌گرا

## اجرای محلی

نیازمندی: Node.js 20 یا جدیدتر.

```bash
npm install
npm run dev
```

سپس آدرس `http://localhost:3000` را باز کنید.

برای ساخت نسخه‌ی نهایی:

```bash
npm run build
npm run qa:fidelity
```

## داده و پایگاه داده

داده‌ها در شروع خالی هستند و در مرورگر با کلیدهای پایدار `mupra-*` نگهداری می‌شوند. برای پاک‌سازی کامل محیط محلی و جدول `workspace_records` از مسیر `/api/records`، آدرس `http://localhost:3000/?reset=1` را یک‌بار باز کنید. تعریف جداول در `db/schema.ts` و مهاجرت‌ها در پوشه‌ی `drizzle` قرار دارند. گردش رسپی، فروش، KDS، مالی و انبار با وضعیت مشترک و پایدار اجرا می‌شود: ثبت خرید موجودی و میانگین قیمت را زیاد و هم‌زمان سند هزینه/پرداخت ایجاد می‌کند؛ اجرای تولید مواد و پرت را کم می‌کند؛ فروش مواد رسپی را کسر و سفارش تولید و دریافت مالی می‌سازد؛ انبارگردانی سند تعدیل ایجاد می‌کند و همه‌ی تغییرات بلافاصله در گزارش بهای تمام‌شده و گزارش‌های مالی دیده می‌شوند.

## سناریوی تست کافه‌رستوران

سناریوی ثبت‌شده و قابل تکرار در نسخه‌ی تحویل‌شده شامل سه صندوق، دو شخص، سه ماده اولیه، یک رسپی «لاته وانیل»، فاکتور خرید چندقلمی، سرمایه و انتقال بین صندوق‌ها، اجاره، حقوق نیمه‌پرداخت، دو صورت‌حساب (یکی پرداخت‌شده و یکی باز)، تسویه کارت‌خوان با کارمزد و خروج مواد رسپی است. اعداد کنترل مستقل سناریو:

- فروش: `۵۵۴٬۰۰۰` تومان؛ خرید مواد اولیه: `۴٬۸۰۰٬۰۰۰` تومان؛ بهای مصرف رسپی: `۱۶۶٬۲۰۰` تومان
- هزینه جاری: `۹٬۰۰۰٬۰۰۰` تومان؛ سود عملیاتی: `−۸٬۶۱۲٬۲۰۰` تومان؛ مانده بدهی حقوق: `۱٬۰۰۰٬۰۰۰` تومان
- مانده کل صندوق‌ها پس از تسویه: `۳۷٬۷۵۰٬۲۶۰` تومان؛ کارمزد تسویه: `۳٬۷۴۰` تومان

سناریو شامل تست منفیِ موجودی ناکافی و تست منفیِ شماره مرجع تکراری نیز هست؛ هر دو فرم را باز نگه می‌دارند و سند نامعتبر ایجاد نمی‌کنند. جزئیات گام‌ها و تصاویر در `docs/QA_DEEP_AUDIT.md` آمده است.

## کنترل کیفیت انجام‌شده

- تطبیق ۷۴ مسیر داخلی با مسیرهای استخراج‌شده از ماپرا و احتساب داشبورد به‌عنوان مسیر هفتادوپنجم
- پیمایش مرورگری همه‌ی ۷۵ صفحه‌ی منویی محلی و بازآزمایی جداگانه‌ی صفحات دارای نام تکراری
- آزمون محصول ← رسپی، رسپی ← تولید ← انبار ← بهای تمام‌شده
- آزمون صورت‌حساب ← KDS ← مالی ← خروج رسپی از انبار و سناریوی جلوگیری از فروش هنگام کسری
- آزمون خرید انبار ← هزینه ← پرداخت مالی
- آزمون viewport واقعی ۳۹۰ پیکسل برای داشبورد، جدول‌ها، مودال‌ها، صورت‌حساب، KDS و ارتقا؛ اصلاح و بازآزمایی سرریز KDS
- موفقیت `npm run lint` و `npm run build`
- موفقیت `npm run qa:fidelity`: تطبیق خودکار ۷۵ مقصد مرجع، بدون مسیر گم‌شده یا اضافه‌ی ناخواسته

نقشه‌ی کامل ماژول‌ها، روابط و مرزهای این نسخه در `docs/SYSTEM_MAP.md` و فایل اکسل همراه پروژه موجود است.

## محدوده‌ی استفاده

این نسخه برای الهام، تحلیل ساختار و ادامه‌ی طراحی ساخته شده است؛ نام تجاری، نشان‌ها و داده‌های خصوصی سایت مرجع کپی نشده‌اند. ظاهر و الگوی تعامل تا حد ممکن به شواهد مشاهده‌شده نزدیک شده، اما کد منبع و سرویس‌های اختصاصی سایت مرجع بخشی از این پروژه نیستند.
